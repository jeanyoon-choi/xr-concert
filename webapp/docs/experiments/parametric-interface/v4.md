# Parametric Interface v4: many phones, many tabs

Started 2026-11-03. Code: `components/parametric-interface/v4/`. Song: ROSÉ, “toxic till the end” (a v4-owned copy of v2’s model and timing).

## Direction

v4 keeps v2's rule: the lyric changes parametrically inside an interface's own semantic slots. What changes is the surface. Instead of one screen, it is many phones and many browser windows. Each one is an ordinary, interactable interface that behaves like a v2 interface: it takes the **whole sung line**, word by word, into its own slot.

Following “1031_NRF XR Idea”, the score assigns every seat a state for t1 ≤ t ≤ t2. The seat stays usable inside that state: a message can be sent, a query typed, a notification opened. The main screen and every seat together make one compositional state. Variety comes from which interface each seat is given. Nobody is handed fragments of the line.

## Routes

| Route | What it is |
| --- | --- |
| `/parametric-interface/v4` | The composition. A 1512 × 945 desk with six browser windows, beside six phones, all on one clock. |
| `/v4/mobiles` | Only the phones, 1–24 of them (`?phones=`). |
| `/v4/tabs` → `/v4/tab` | Real windows. The controller opens pop-ups, and each pop-up follows the controller's clock. |

## Shared parts

| Part | File | Role |
| --- | --- | --- |
| Song clock | `clock/` | `AudioSongClock` owns the one `<audio>` element (v2's playback, plus a transport and a clock anchor). `FollowerSongClock` extrapolates an anchor broadcast by another tab. It holds its position once the owner has been silent for 3.5 s. |
| Lyric timeline | `timeline/` | Keeps v2's 120 ms lead. `wordIndex` is −1 before the first word. `useSungLines` returns the arrived lines, and one array is shared by every surface on a page. |
| Lines | `model/lines.ts` | `sungLines`: oldest line first; the last line grows word by word. It is a pure function of the clock, so late joins and reloads rebuild the same state. |
| Score | `model/score.ts` | Time sections, each assigning a phone state and a tab page per seat (see below). |

### The ROSÉ score

| Section | Phones | Tabs |
| --- | --- | --- |
| Verses | Mixed: Messages, Assistant and Lock screen | Mixed: Search, News and Billboard |
| Choruses | All on the lock screen | All Billboard |

Verses scatter the line across interfaces; choruses pull everything into unison.

## Phones: `mobiles/`

The phone grid follows experiments-jyc goldfishes `pc/mobiles/1`. `fitPhoneGrid` sizes a 404 × 858 iOS frame, and CSS `zoom` scales it as one unit. `mobiles/grid.tsx` fits the phones into any box: the whole page in `/v4/mobiles`, or one pane of the composition.

**States.** A state is a folder under `mobiles/apps/<state>/` plus an entry in `apps/registry.ts`, and it meets `apps/types.ts`. Every state stays mounted, so a thread's scroll and draft survive the score moving away and back. Each seat has its own contact and wallpaper.

- **Messages** (as in v2/7): each line arrives from the seat's contact as one incoming bubble and fills word by word. The thread opens with an ordinary exchange from before the song. The input bar is real; a reply lands after the line it answered.
- **Assistant:** a chat-assistant app. Lines alternate between the person and the assistant. The person's line is typed into the composer, then sent when the next line starts. The assistant's line streams, with a dot riding its end. The seat picks which side opens, so nearby phones differ. The composer is real.
- **Lock screen:** each line is a Messages notification, newest on top, older ones folded. Tapping one opens the thread until the next section.

## Tabs: `tabs/`

The real windows follow experiments-jyc SCC `desktop-collage/foundations/browser`: same-origin pop-ups opened from one click as a grid, a cascade or plain tabs. Only the browser path was ported; there is no Mac helper and no server.

**Sync.** The controller tab owns the audio and a roster. Lyric tabs say hello once a second over a `BroadcastChannel` (`tabs/channel.ts`). The controller answers with the clock anchor and the roster in seat order. A tab drops out after 3.2 s of silence.

**Pages.** A page is a folder under `tabs/pages/<state>/` plus an entry in `pages/registry.ts`. Pages lay out in CSS px against their container, never the viewport. The window writes the sung line as its own tab title.

- **Search** (a fictional engine, lookup): the sung line types into the query box. Earlier lines come back as results, each with the line before it as the snippet. Before the song it shows the engine's empty home page. The box is editable.
- **News** (The Evening Line): the sung line is the live lead headline, the line before it is the standfirst, and earlier lines run down the Latest column.
- **Billboard:** a street poster. The whole line is one block of condensed type, and each word turns solid as it is sung. Every seat is printed in its own colours.

**Previews.** `tabs/frame` draws a browser window (traffic lights, a tab carrying the title, the address, the page). `tabs/desk` draws a screen at real px and zooms it to fit. The controller's preview and the composition both use these, so they show what the opened windows show.

## Invariants

- No socket events, relay or server state. Phones on one page share one clock, and tabs of one browser share one `BroadcastChannel`. Real separate phones would need the concert relay, and that is a separate, explicitly scoped step.
- Only the clock owner plays audio. Followers never do.
- Phone text uses iOS's own point sizes inside a zoomed frame. This is a PC simulation of many phones, not a participant mobile surface.
