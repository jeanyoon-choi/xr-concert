# Parametric Interface v4: many phones, many tabs

Started 2026-11-03. Code: `components/parametric-interface/v4/`. Song: ROSÉ, “toxic till the end” (a v4-owned copy of v2’s model and timing).

## Direction

v4 keeps v2's rule: the lyric changes parametrically inside an interface's own semantic slots. What changes is the surface. Instead of one screen, it is many phones and many browser windows. Each one is an ordinary, interactable interface that behaves like a v2 interface: it takes the **whole sung line**, word by word, into its own slot.

Following “1031_NRF XR Idea”, the score assigns every seat a state for t1 ≤ t ≤ t2. The seat stays usable inside that state: a message can be sent, a note written, a notification opened. Every seat together makes one compositional state. Variety comes from which interface each seat is given. Nobody is handed fragments of the line.

## Routes

| Route | What it is |
| --- | --- |
| `/v4/1` | `1_mobiles/`: the phones, 1–24 of them (`?phones=`, default 12), each keeping one app. |
| `/v4/2` | `2_mobiles/`: 1's phones moving between apps together, by passage (below). It shares `model/` (song, lines, score) with 1. |

## Shared parts

| Part | File | Role |
| --- | --- | --- |
| Song clock | `clock/` | `AudioSongClock` owns the one `<audio>` element (v2's playback, plus a transport and a clock anchor). `FollowerSongClock` extrapolates an anchor broadcast by another tab. It holds its position once the owner has been silent for 3.5 s. |
| Lyric timeline | `timeline/` | Keeps v2's 120 ms lead. `wordIndex` is −1 before the first word. `useSungLines` returns the arrived lines, and one array is shared by every surface on a page. |
| Lines | `model/lines.ts` | `sungLines`: oldest line first; the last line grows word by word. It is a pure function of the clock, so late joins and reloads rebuild the same state. |
| Score | `model/score.ts` | Time sections, each assigning a phone state and a window interface per seat (see below). |

## Phones: `1_mobiles/` (and its copy `2_mobiles/`)

The phone grid follows experiments-jyc goldfishes `pc/mobiles/1`: `fitPhoneGrid`, with a 404 × 858 iOS frame zoomed as one unit. `1_mobiles/grid.tsx` fits the phones into any box.

The lyric is someone texting an ex, so the phones are the places a phone holds text. There are seventeen states, each a hyper-real app that takes the line in a slot of its own. Each folder's header comment records its sources: measured SCC replicas, platform-served assets, or, where none was available, glyphs drawn by eye, said so.

| State | Where the line goes |
| --- | --- |
| Messages | Incoming bubbles from the ex |
| KakaoTalk | A group room: friends post the lines in turn, and the unread counts drop |
| Instagram DM | The ex replies to your story, line by line |
| WhatsApp | "typing…" while sung; the line arrives when finished |
| X | Your own self-thread: typed in the composer, then posted |
| ChatGPT | Prompts and streamed answers in turn |
| Telegram | One message per line, edited word by word ("edited") |
| TikTok | The video's auto-caption |
| Slack | A coworker's consecutive messages in #late-night-edit, with reactions |
| Instagram | The post's caption (first line), then comments |
| LINE | You type each line and send it; "Read" appears |
| Discord | A friend posts it while "typing…" shows |
| YouTube | A live stream's chat, one viewer per line |
| Threads | Strangers' posts arriving at the top of For you |
| Messenger | You send each line, then unsend it ("You unsent a message") |
| Notes | A note she doesn't send |
| Lock screen | Notifications from the app the phone holds in the verses, in that app's wording, under its App Store icon |

Seats take the first sixteen in order, so twelve phones never repeat an app, and keep them the whole song. Only while a “We were toxic …” line is sung (seven in the song) does every phone fall to its lock screen; the next line returns each to its app. Every lyric slot types character by character (`timeline/use-sung-lines.ts`: about 55 ms a character, never running past the next word). Only the shown state and the lock screen are mounted on a phone. Participants can send, post or comment in every app, and what they send stays.

## 2_mobiles: phones on their own

`/v4` opens 2. It starts as a copy of 1 and differs in three ways.

- **Hops (`2_mobiles/hops.ts`):** after goldfishes `pc/mobiles/1`, phones move between apps by passage.
  - **Passages:** the lyric is divided into passages, wider than a line and narrower than a verse (`PASSAGES`, 20 in the song). Each “We were toxic …” line is a passage of its own.
  - **The roll:** when a passage ends, the dice decide once for the whole grid, with a 70 % chance of moving. Either every phone moves to another app together, at least four places along the app list so no phone takes its neighbour's, or none does. No two phones ever share an app.
  - **Motion:** a move is a scroll (`MOVE_MS`, 750 ms), eased in and out. The new app rises from below as the old one is carried up with it, as one sheet. Only transform animates.
  - **Timing rule:** a move's midpoint always falls on the first word of the new passage. It starts `MOVE_MS / 2` before and ends `MOVE_MS / 2` after, whatever `MOVE_MS` is. The CSS reads the duration from `MOVE_MS`.
  - **Preloading:** the next app is mounted out of sight below the glass up to 0.7 s ahead (each phone a little apart), so when the move starts nothing mounts and the frame never stalls.
  - **Determinism:** the dice are hashes of the passage, so reloads and seeks land on the same apps.
- **Lock screen:** on every “We were toxic …” line, the lock screen comes down over whatever app is open. It goes back up on the next line.
  - The layout follows SCC `mobiles/1`'s measured one: padlock, date, a 108 pt clock, flashlight and camera.
  - Notifications come from the app the phone was in, worded as that app, under its App Store icon. iOS groups one app's notifications, so the newest card is in front and earlier ones peek beneath as slivers.
  - Wallpapers are 12 photographs a person would set: couples, rain at night, dying roses, a sunset. They are CC0 or CC BY, from Flickr via Openverse, credited in `public/parametric-interface/v4/wallpapers/attribution.json`. A light shade keeps the clock legible.
- **Status bar:** each phone has its own signal (1–4 bars), Wi-Fi (1–3 arcs) and battery level, red at 20 % or below.

## 3_mobiles: the extension

`/v4` opens 3. It is a copy of 2 with its own state list (`3_mobiles/states.ts`) and the following changes.

**More text interfaces: 29 apps in all.** Only interfaces that belong to this situation (a relationship and its end) are kept. Calendar, Voice Memos, Papago, Reminders, 토스, 배달의민족, Duolingo, Apple Music (which names the song), YouTube live and Slack were tried and removed. No interface names the song or the singer. Each app takes the line in its own slot:

**Sources.** Each folder's header records them.
- **Platform assets:** where a platform serves its own, they are used: Google's logo and sprite, kin's SVGs, Everytime's icon font, Blind's sprite, Daangn's SEED icons, Signal-iOS symbols, Reddit's published icons, the Gemini sparkle.
- **Drawn glyphs:** elsewhere glyphs are drawn and say so.
- **Lock-screen icons:** each app's App Store artwork (`public/parametric-interface/v4/icons/`).

**Real time.** Every time and date a phone shows is the wall clock now.
- `3_mobiles/clock-face.ts` anchors song time to the wall clock, so a line's stamp is the minute it was sung.
- Content from before the song is dated minutes before now (`clockAgo`), and dates are today (`dateLabel`).

**Measured.** At 12 phones: 60 fps, with no frame over 34 ms through a passage move.

## Windows: `tabs/` and `interfaces/`

A window runs one of v2's eight interfaces: the yes/no grid, the lyric sheet, the macOS menu bar, the departures board, Gmail, Terminal, Messages and Find My. The interfaces are copied into `interfaces/` unchanged. Each one is already a hyper-real, lyric-responsive whole screen, and a browser window is a screen. Only their playback is replaced (`interfaces/playback`): it reads v4's clock, so no window owns audio.

- **`/v4/tabs`** is the controller: the browser path of SCC `desktop-collage` (pop-ups as a grid, a cascade or tabs). Its preview is desktop-collage's plain schematic of the plan, each window labelled with its seat and interface. The windows follow the controller's clock over a `BroadcastChannel` and take their seat from its roster.
- **`/v4/tab`** is the window page.

## Invariants

- No socket events, relay or server state. Phones on one page share one clock, and tabs of one browser share one `BroadcastChannel`. Real separate phones would need the concert relay, and that is a separate, explicitly scoped step.
- Only the clock owner plays audio. Followers never do.
- Phone text uses iOS's own point sizes inside a zoomed frame. This is a PC simulation of many phones, not a participant mobile surface.
